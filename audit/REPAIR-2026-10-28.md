# إصلاح Fox5517 وتجهيز Windows — تقرير التحقق

**التاريخ:** 2026-10-28. المستخدم أجاز الإصلاح وتجهيز جهازه بعد مرحلة «الاختبار فقط». الأصل ثابت في `vendor/FoxConquer5517`، والعمل المعدل في `src/FoxConquer5517`. [تقرير baseline](REPORT-2026-10-28.md) لم يتغير لإخفاء إخفاقاته.

## النتيجة التي ثبتت حتى الآن

- **64 من64 اختبار مكونات نجحوا** على Windows2022 وUbuntu24.04.
- Debug وRelease على النظامين: **صفر errors و18 warning لكل build**. التحذيرات معلنة، وليست أخطاء جرى إسكاتها.
- SDK مثبت: **10.0.403**؛ runtime الفعلي **.NET10.0.14، X64**.
- نجح الإعداد المعزول على MariaDB10.4.32: قواعد جديدة، لا حسابات/شخصيات قديمة، حساب اختبار عادي، مستخدم DB محدود، vault واختبار DPAPI على Windows، والتحقق من config.
- بدأ LoginServer وMsgServer وحمّل الأخير الخرائط والداتا، وسجّل نفسه لدى LoginServer.
- **محاكاة دخول على loopback نجحت**: طلب1060 مجزأ، رد1055، عنوان وبورت صحيحان، ووصول token إلى قائمة انتظار MsgServer. لا تنفيذ لعميل TQ أو لودر المستخدم.
- **الإيقاف المنظم نجح، والحزمة أُنتجت ونُشرت بعد نجاح البوابة كاملة.** تتبع [PR #3](https://github.com/ahmedzahran7710-prog/Red-Moon/pull/3) الدمج والتحقق النهائي على main؛ لا نفترض حالة مستقبلية قبل حدوثها.

## الإصلاحات الأساسية

### استقبال وإرسال الشبكة

- استقبال TCP مشترك بحدود واضحة للأدوار الثلاثة: اتصالات اللاعبين، الاتصال الصادر، والربط الداخلي.
- تجميع header وbody المجزأة، ومعالجة frames المتتابعة دون افتراض أن كل Receive تساوي رسالة واحدة.
- رفض الأطوال الأصغر من header، والأطوال/الأنواع المتجاوزة للحدود، دون كتابة خارج buffer.
- قراءة DH envelope بحجم محدود، وعدم استهلاك frame تالية بمفتاح التشفير القديم.
- استكمال bytes المتبقية عند partial `Socket.Send`.
- إغلاق connection وإشعار cleanup مرة واحدة بشكل متزامن، بدل إنهاء العملية قبل callback الحفظ. إعادة الربط تنشئ socket جديدة.
- عدم إعادة `BeginAccept` على listener مغلقة. خطأ cleanup لا يفلت من callback الشبكة ليقتل بقية السيرفر.

### صحة البيانات والـpackets

- حدود لكل عمليات القراءة/الكتابة الأساسية في PacketStructure.
- CP1252 مهيأ عند المكوّن نفسه، لا اعتمادًا على side effect لتهيئة DB.
- قص النص عند حد الحقل وحرف كامل، مع اختبار UTF8 وحقل أصغر من أول حرف.
- `WriteArray` تنسخ البيانات بدل مرجع array، وlength-prefixed strings لا تتجاوز المجال.
- قراءة كلمة السر من16 بايت محددة، لا `new string(pointer)` تبحث خارجها عن NUL.
- حلقات RC5 تستخدم قراءات وكتابات little-endian مُدارة، لا pointer انتهت صلاحية تثبيته.
- تصحيح SHIFT في inverse encoder المستخدم بالمحاكاة، مع roundtrip لحروف مختلطة وكلمة بطول16.

### ربط LoginServer وMsgServer

- عنوان ومنفذ redirect من config، بدل العنوان التجريبي الثابت وبورت hardcoded.
- تحميل بيانات الربط وtransfer keys بشكل متسق بين العمليتين، وقراءة منفذ DB في كل factory.
- إصلاح أطوال رسائل **البروتوكول الداخلي فقط**: كانت buffers تضم padding بينما header تعلن طولًا أقل؛ صارت متفقة مع البايتات الفعلية. **لا تخلط LoginServer قديمة مع MsgServer من الحزمة الجديدة.**
- Getter اسم السيرفر يحترم length prefix، مع roundtrip للاسم والبورت والاعتماد.
- تهيئة MAC فارغة بدل طول عشوائي في رسالة تمرير الحساب، ونقل VIP/authority/MAC المعروفة وحفظها في LoginRequest.
- اختبار التكامل لا يكتفي برد الدخول: يشترط وصول `REDMOON_AUTH_TOKEN_QUEUED` وعدم رفض packet أو سقوط الرابط.

### Arena وVIP

- Arena تستخدم نفس النقاط والعتبات الأصلية، لكن تُقيّمها بالترتيب الذي يجعل الفئات الخمس قابلة للوصول. لا تغيير rates أو تصميم اقتصاد جديد.
- تنقل المدن الخمس وساحاتها يستخدم إحداثيات `cq_map.portal0`، وفُحصت tiles الأصلية وكانت قابلة للمشي.
- حساب Vip0 لا يستخدم handler التنقل. الوجهات التفصيلية غير المتحققة والـteamteleport ترد برسالة بدل إرسال اللاعب إلىTwinCity بالغلط.
- هذا **ليس إكمالًا لكل مزاياVIP أو اعتمادًا لتوازن امتيازاته**؛ لا VIP/GM تلقائية لحساب التثبيت الأول.

### التشفير وruntime

- اسم الكلاس القديم BlowfishCipher مضلل: الفرع النشط في المصدر ينادي **CAST5**. البديل هو managed **CAST5-CFB64**، لا Blowfish أوCFB8.
- اختبار known-answer من OpenSSL النظامي مستقل عن مكتبة .NET، واختبارات chunking وIV وإعادة المفتاح وحد16 بايت لسرDH الطويل.
- أسDH خاص بكل اتصال من SecureRandom، وpublic keys متحققة؛ مجموعة protocol الخاصة بـ5517 لم تُغيّر.
- لا استخدام لـ`libeay32.dll` الأصلية غير المتحققة في التشغيل الجديد، ولا فرضx86 لإخفاء عدم التوافق.
- working source على.NET10LTS مع BouncyCastle.Cryptography2.7.0 وNHibernate5.7.0 وFluentNHibernate3.5.0 وMySql.Data9.7.0. baseline باقية كما كانت على3.1.

## تجهيز جهاز المستخدم وحماية بياناته

- الإعداد غير السري يتضمن المسارين اللذين حددهما المستخدم وHamachi وعناوين وبورتات مستقلة.
- DB والربط الداخلي على loopback فقط؛ لا firewall أوrouter أوantivirus changes تلقائية.
- إنشاء `redmoon_account` و`redmoon_game` جديدتين فقط؛ توقف عند التصادم مع قواعد/مستخدم قائمين. لاDROP ولا إعادةseed فوق بيانات قديمة.
- allowlist لبيانات اللعبة المرجعية؛ إزالة حسابات/شخصيات/مخزون وحالة اللاعب القديمة منseed المشتقة، دون تحرير الأرشيف الأصلي.
- سكربت رسائل upstream كان يستهدف `zf.cq_action` صراحة. أصبح patch مولدًا غير مؤهل باسمschema، يعمل داخل قاعدة جديدة محددة فقط، مع guard واختبار منع cross-schema.
- كلمة مرورroot تدخل محليًا مرة واحدة ولا تُحفظ. أسرار تشغيل مولدة في vault محلية DPAPI، وconfig تحتوي مراجع environment بدل passwords.
- المستخدم التشغيلي محدود الصلاحيات. حساب اللعبة الأول عادي، بكلمة مختلفة من8–16 حرفًا إنجليزيًا/رقمًا بسبب حدود لوحة مفاتيح العميل القديم.
- Start يراجع عنوانHamachi والمنافذ والجاهزية والربط. Stop يطابق اسم executable ومساره ووقتPID، ويرسل علامة إيقاف داخل نفسinstallation دونforce-kill.
- قراءة process records تُختبر على **Windows PowerShell5.1**، وليس PowerShell7 وحدها؛ قراءة root JSON array تختلف بينهما وكانت سببًا لعطل stop.

## إعداد العميل وحدوده

راجعنا schema **config.json** في سورس ConquerLoader عندtagv1.0.1.0. أداة التجهيز تنتج إعداد5517 ثم تتحقق من `version.dat` وmetadata اللودر قبل نسخها، وتحفظ backup وتوقف العمل عند `config.json.lock`.

لا تعديل لـ`Conquer.exe` أو `Server.dat` أو `GameServer.ini` أو ملفاتMoonQueen، ولا تشغيل loader/عميل داخل CI، ولا تعطيل حماية. metadata الاسم/الإصدار ليست شهادة توقيع أو فحصmalware. استخدام اللودرين سابقًا مع5187 لا يثبت توافقهما مع5517.

# فحص النسخة الأصلية — FoxConquer5517

**النطاق: استيراد واختبار فقط، من غير إصلاح السورس أو تغيير إعداداته.**

## ما الذي نُقل إلى Git؟

- النسخة المثبتة: [`darkfoxdeveloper/FoxConquer5517@70f3560465ba73cef0250109af7cf167b508516f`](https://github.com/darkfoxdeveloper/FoxConquer5517/tree/70f3560465ba73cef0250109af7cf167b508516f).
- `vendor/FoxConquer5517` يحتوي 636 ملفًا أصليًا، حجمها الإجمالي 3,865,911 بايت؛ تشمل **كل ملفات C# الـ615 وكل المشاريع الأربعة والـsolution** والترخيص وملفات صغيرة أخرى.
- كل ملف مستورد مطابق بالبايت للمصدر؛ لا تحويل CRLF/BOM، ولا تعديل C#/csproj/SQL/config، ولا نسخ معدلة لتجاوز فشل الاختبارات.
- [الترخيص الأصلي](../vendor/FoxConquer5517/LICENSE) محفوظ كما هو. وجود MIT للكود لا يثبت حقوق توزيع العميل أو جميع موارد اللعبة؛ لم يُوزع العميل هنا.
- [الـmanifest](fox5517-manifest.json) يسرد ملفات الأرشيف الـ810 كلها مع الحجم وSHA-256 وما إذا كانت ضمن Git وسبب الاستبعاد.

## ما المستبعد، ولماذا؟

النسخة الكاملة تفك إلى **278,410,351 بايت**، بينما ZIP الأصلي 4,495,988 بايت. ليست الملفات الـ636 وحدها توزيعة تشغيل مكتملة.

- `RequiredFiles/Maps/`: 165 ملفًا، 262,966,500 بايت. موارد كبيرة، وليست تعديلات كود.
- `Database/accountzf.sql` و`Database/zf.sql`: يحتويان حسابات وسجلات لعب قديمة. لا تُنسخ القيم إلى Git أو تقارير الاختبار، ولا نبدلها ونزعم أن الملف الأصلي لم يتغير.
- `ExampleConfig/`: أمثلة إعدادات الاعتماد الأصلية؛ لا تُطبق على بيئة المستخدم تلقائيًا.
- `LoginServer/libeay32.dll` و`MsgServer/libeay32.dll`: ملفات native أصلية تُجلب مؤقتًا للتحقق من الهوية/البنية ولتكون ملفات مشروع البناء كاملة، **لا تُنفذ في هذا الفحص**.
- `.gitattributes` و`.gitignore` الأصليان: سياسة upstream الداخلية لا تُطبق داخل vendor؛ سياسة Red Moon تحفظ بايتات المصدر بدل تطبيعها.

الاستبعاد صريح، **وليس حذفًا أو إصلاحًا داخل المصدر**. يمكن إعادة تكوين الأرشيف الكامل في scratch من الرابط المثبت مع التحقق من كل ملف. لم يُرفع ZIP مكرر أو خرائط كبيرة إلى Git.

## إعادة التحقق والتجهيز

تحتاج Python 3.9 أو أحدث، بلا حزم إضافية. من جذر Red-Moon:

```bash
python tools/fox_baseline.py verify
python -m unittest discover -s tests -p "test_*.py" -v
python tools/fox_baseline.py materialize
python tools/fox_baseline.py verify --source .cache/fox5517/original --full
```

`materialize` ينزل ZIP المثبت إلى `.cache/fox5517/upstream.zip` ويفكه إلى `.cache/fox5517/original`، وكلاهما خارج Git. لا يغير الملف الموجود؛ عند إعادة التشغيل يتحقق من النسخة الموجودة بدل الكتابة فوقها. إذا كانت النسخة ناقصة/مختلفة يتوقف، ويُفضل اختيار مجلد scratch جديد بدل الكتابة فوق عمل محلي. لا يستورد SQL ولا يبدأ سيرفرًا.

## الاختبارات المنفصلة عن السورس

[Workflow الفحص](../.github/workflows/fox5517-baseline.yml) يطلب:

- Windows 2022، SDK **3.1.426**، `netcoreapp3.1` الأصلي، restore ثم Debug وRelease. لا تغيير target framework ولا أسماء المكتبات لجعل البناء يمر.
- برنامج managed صغير في `tests/managed` يختبر بايتات رد الدخول، حدود كتابة الحقول، فئات نقاط Arena، وقراءة النص في process جديدة، وإعادة تجميع TCP عبر sockets على loopback فقط (frame كاملة / body مجزأة / header مجزأة). يشير إلى مشاريع المصدر الأصلية، ولا يبدأ LoginServer/MsgServer أو يستدعي native crypto.
- MariaDB **10.4.32** في container مؤقت على runner آخر، للاستيراد إلى خادم فارغ فقط. جداول/إجراءات SQL لا تعادل اختبار NHibernate أو حفظ اللعب. إجراءات المخزن تُعرّف فقط ولا تُستدعى.
- `tools/sql_probe.py` يرفض العمل خارج CI المعزولة أو على خدمة ذات قواعد مستخدم موجودة. لا أداة ترحيل لجهاز المالك، ولا تتصل بعناوين Hamachi/DB الخاصة به. خدمة الاختبار منشورة على loopback فقط، ولا تستخدم كلمات مرور المالك.
- التأكد بعد العمل أن **كل ملفات المصدر الأصلية ما زالت مطابقة**.

**الفشل يظل فشلًا:** البرنامج يعيد exit code غير صفري عند فشل assertion. لا `continue-on-error` ولا إخفاء لفشل البناء. قد تكون CI حمراء لأن هذه نسخة baseline بها أخطاء، والمستخدم لم يسمح بإصلاحها بعد؛ لا نعتبر ذلك اختبارًا ناجحًا ولا نتجاوز حماية/check مطلوب للدمج.

مخرجات CI النصية المنقحة تُحفظ artifacts لمدة7 أيام، وتُنشر JSON صغيرة أيضًا كـannotations يمكن قراءتها عبر GitHub API؛ تنزيل artifacts من تخزين Azure غير متاح في شبكة هذه الجلسة. لا تُرفع ملفات SQL الخام أو configs أو binaries أو خرائط. ستُحفظ خلاصة النتائج والمراجع الدائمة في تقرير هذه الجولة بعد اكتمال المحاولة؛ إعداد workflow وحده ليس نتيجة اختبار.

## حدود التقييم

لا كلاينت، لا اتصال لاعب، لا تشغيل سيرفر عام، لا اختبار قتال/تجارة/حفظ فعلي، ولا ضغط/soak test. لا تغييرات تصميمية، لا تشغيل على جهاز المالك، ولا اعتماد النسخة للإنتاج. الـSDK القديم مطلوب هنا لإعادة إنتاج baseline، وليس توصية بأمان استخدامه على الإنترنت.

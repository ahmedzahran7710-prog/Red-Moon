# تشغيل Red Moon على جهاز أحمد — Windows

> **تجربة محلية/عبر Hamachi، مش إعلان جاهزية للإطلاق العام.** تجهيز السيرفر لا يثبت دخول عميل TQ فعليًا. راجع [تقرير الإصلاح](../audit/REPAIR-2026-10-28.md) لمعرفة آخر اختبارات أُنجزت وما بقي.

> **تصحيح 2026-10-29:** لو ظهر خطأ `Split-Path / Path is an empty string` عند فتحSetup، استخدم [تصحيح ملفات التشغيل الصغير](HOTFIX-2026-10-29.md). الحزم القديمة المشار إليها أدناه قد تحتاج هذا التصحيح؛ لا تعالج الخطأ بحذف DB أو تغيير كلمة المرور.

## تختار أي تنزيل؟

**[تنزيل حزمة Windows التي اجتازت الاختبار الكامل](https://github.com/ahmedzahran7710-prog/Red-Moon/actions/runs/40622014775/artifacts/12787283740)** — حوالي48MB داخل ZIP التي يقدمها GitHub. افتح الرابط وأنت داخل حسابك؛ المستودع خاص. مرجع حزمة أحدث بعد آخر توثيق قد يوجد في PR#3.


- **للتشغيل من غير بناء يدوي:** حزمة Actions المسماة `RedMoon-Windows-x64`، من تشغيل ناجح للـworkflow `Red Moon repaired source and Windows package`. الحزمة لا تُنتج إلا بعد نجاح اختبارات المكونات، والإعداد وتشغيل وربط السيرفرين والإيقاف المعزول على Windows. فيها ملفات الكود، executables ذاتية الاحتواء، الخرائط وSQL النظيفة، ولا تضم كلاينت أو لودر أو كلمات مرور.
- **Code → Download ZIP من GitHub:** كود فقط، وليس نفس حزمة التشغيل. لو اخترته، استخدم `Build-RedMoon.cmd`؛ يحتاج SDK **10.0.403** وPython3.9+ وإنترنت لاستعادة الحزم والأصول المثبتة. وجود Visual Studio وحده مش دليل إن SDK المطلوبة مثبتة.
- ملفات Git الكبيرة/الحساسة لا تُنسخ عشوائيًا. أصل السورس في `vendor`، والكود المعدل في `src/FoxConquer5517`، والـsolution للعمل هي `src/FoxConquer5517/FoxConquer5517.sln`.
- في حزمة التشغيل، `bundle-manifest.json` يسجل commit المصدر وSHA256 لكل ملف، وملف JSON بجانب ZIP يسجل hash الأرشيف. artifacts مؤقتة30 يومًا؛ عند انتهاء المدة أعد تشغيل workflow من نسخة معروفة.

## 1. فك الحزمة في المكان الصحيح

لو تنزيل Actions أعطاك ZIP خارجية تحتوي `RedMoon-Windows-x64.zip`، فك الداخلية أيضًا. حط **محتوياتها** مباشرة في:

```text
F:\AhmedZahran\RedMoon\RedMoon-Sorce
```

يعني تلاقي `Setup-RedMoon.cmd` و`Start-RedMoon.cmd` ومجلد `server` داخل المسار ده، مش داخل مجلد إضافي. اسم `Sorce` متروك كما أرسلته.

الكلينت الحالي يفضل في:

```text
F:\AhmedZahran\RedMoon\RedMoon-Client
```

ما تنسخش ملفات السيرفر فوق العميل، وما تمسحش نسختك القديمة. ما تخلطش LoginServer من نسخة قديمة مع MsgServer من الجديدة، لأن بروتوكول الربط الداخلي اتصلّح في الطرفين. حزمة التشغيل لا تحتاج تثبيت .NET Runtime أو SDK للتشغيل، لكنها **Windows x64**؛ لا نفترض صلاحية جهاز32-bit أو كل إصدارات Windows القديمة.

## 2. شغّل البرامج الموجودة عندك

- شغّل MySQL من XAMPP وتأكد أنه يعمل على `127.0.0.1:3306` وبنفس **MariaDB10.4.32** التي راجعناها. Apache ليس شرطًا لتشغيل اللعبة.
- شغّل Hamachi وتأكد أن عنوان جهازك ما زال `25.21.212.130`. أداة البدء تتوقف لو العنوان غير موجود بدل ما تستخدم عنوانًا خاطئًا.
- اقفل فقط أي **نسخة سيرفر تخصك وتعرفها** تستخدم9958 أو5816 أو9865. الأداة لا تقتل برنامجًا مجهولًا لإخلاء منفذ.

الإعدادات غير السرية في `setup/owner-profile.json`:

- الدخول: `25.21.212.130:9958`.
- اللعبة والعنوان الذي يرجع للعميل بعد تسجيل الدخول: `25.21.212.130:5816`.
- اتصال LoginServer ↔ MsgServer: `127.0.0.1:9865` فقط.
- DB: `127.0.0.1:3306` فقط.
- اسم السيرفر: `RedMoon`، ورقم العميل المتوقع5517.

**لا تفتح3306 أو9865 للاعبين، ولا تستبدل عنوان DB بعنوان Hamachi.**

## 3. إعداد مرة واحدة — من غير مسح الداتا القديمة

شغّل `Setup-RedMoon.cmd`:

1. هيسألك محليًا عن كلمة مرور `root` الحالية. **لا تبعتها تاني في المحادثة**؛ القيمة ليست مكتوبة في GitHub ولا في الحزمة.
2. اختار اسم حساب لعبة جديد من3–16 حرفًا إنجليزيًا/رقمًا/underscore.
3. اختار **كلمة سر لعبة مختلفة** من8–16 حرفًا إنجليزيًا أو رقمًا، بدون رموز أو مسافات؛ المصدر القديم فيه normalization خاص بلوحة مفاتيح العميل، فلا نفترض أن كل علامات الترقيم مدعومة.

الأداة تنشئ قواعد جديدة:

```text
redmoon_account
redmoon_game
```

وتنشئ مستخدم تشغيل `redmoon_runtime` محدودًا بالجداول/الإجراءات المطلوبة داخل القاعدتين، بدل تشغيل اللعبة بحسابroot. لا تغيّر كلمة مرورroot ولا إعدادات XAMPP، ولا تستورد حسابات/لاعبين upstream القديمة. حساب اللعبة الأول **عادي**: لا GM/VIP/CPs تلقائية.

لو أي قاعدة مستهدفة أو مستخدم runtime موجودين بالفعل، الأداة تتوقف **من غير DROP أو استبدال**. لا تمسحهم لمجرد إعادة المحاولة؛ راجع الحالة أو استخدم أسماء جديدة في profile لا تتصادم مع قواعد قديمة. في الفشل الجزئي لا نحذف قواعد أُنشئت خلسة ولا نعيد تحميل SQL فوق بيانات قد تكون تغيرت.

الأسرار المولدة للتشغيل تُحفظ داخل `.local/runtime-secrets.dpapi` مشفرة لحساب Windows الذي شغّل الإعداد. ملفات `server/Login.cfg` و`server/Shell.ini` تشير لمتغيرات بيئة، لا تحتوي كلمة مرورroot. احتفظ بمجلد `.local` محليًا، **ولا ترفعه إلى GitHub أو تبعته مع logs**. تشغيل الملفات تحت حساب Windows آخر يحتاج مراجعة الإعداد، لأن DPAPI مرتبطة بالحساب.

لو `mysql.exe` مش موجود في PATH أو مواقع XAMPP/MariaDB المعتادة:

```powershell
.\setup\Setup-RedMoon.ps1 -MysqlExe "C:\xampp\mysql\bin\mysql.exe"
```

استبدل المسار بمكانه الحقيقي فقط؛ HeidiSQL مش بديلًا عن executable الـCLI. لو التشغيل خلص هتشوف `SETUP_OK`.

## 4. تشغيل وإيقاف السيرفرين

- شغّل `Start-RedMoon.cmd` وانتظر تحميل الخرائط.
- الأداة تستنى readiness للـLoginServer والـMsgServer، وكمان تسجيل MsgServer لدىLoginServer، قبل طباعة `SERVERS_READY`.
- تستخدم نفس الملفين ذاتيي الاحتواء اللي تنشرهم CI؛ لا تعتمد على وجود SDK في جهازك.
- logs محلية في `.local/logs`. لو فيه عطل، ابعت **آخر رسالة خطأ بعد تنقيحها**، مش مجلدالأسرار ولا ملفات DB.
- للإيقاف استخدم `Stop-RedMoon.cmd` قبل غلق MySQL. بيطلب إيقافًا وحفظًا بالطريقة البرمجية ولا يعملforce-kill لو الحفظ اتأخر. يتأكد من executable ووقت إنشاءPID قبل التعامل معه.

ملفاتCMD تستخدم `-ExecutionPolicy Bypass` **للعملية الحالية لتشغيل سكربتات هذا المشروع فقط**؛ لا تغيّر execution policy على الجهاز، ولا تضيف antivirus exclusions أو تعدّل Defender. لو برنامج حماية منع executable، لا تقفل الحماية؛ تحقق من المصدر/الـhash وشارك رسالة المنع أو ابنِ من السورس.

## 5. إعداد اللودر الذي أرسلته — من غير العبث بالكلينت

الصورة الأولى أظهرت `Conquer.exe` و`Server.dat` و`GameServer.ini` و`version.dat`؛ والصور اللاحقة أظهرت `ConquerLoaderV1.0.1.0.zip` ونسخة `MoonQueenLoader` كنت تستخدمهما مع5187. ده **مش فحص توافق5517 أو سلامة binary**.

المسار الذي جرى مراجعته في GitHub هو `ConquerLoader` الأصلي، schema ملف **`config.json`** عند tagv1.0.1.0، وليس افتراض ملفLoaderSet.ini. الخطوات:

1. تأكد أن `ConquerLoader.exe` الذي حملته من ناشره الأصلي موجود داخل مجلد العميل. **لا تغيّر اسم MoonQueenLoader لتجاوز التحقق**، ولا تستبدل `Conquer.exe`.
2. شغّل `Install-ClientConfig.cmd`. الأداة تولد نسخة في `client-config/config.json` أولًا.
3. تثبّت الإعداد فقط إذا كان `version.dat` يذكر5517، وكان metadata اللودر يطابق الاسم/الإصدار الذي راجعناه. metadata للتحقق من **صيغة الإعداد** وليست شهادة مضاد فيروسات/توقيع.
4. لو وجدت `config.json` قائمة تعمل لها نسخة احتياطية. لو وجدت `config.json.lock` تتوقف ولا تحذفها أو تتجاوزها. لا تعدّل ملفاتMoonQueen أو `Server.dat` أو `GameServer.ini` أو executable العميل.
5. شغّل `ConquerLoader.exe` بنفسك، واختار `RedMoon [5517]` ثم جرّب حساب اللعبة الجديد. لا تشغّل `AutoPatch.exe` لتحديث العميل تلقائيًا إلى باتش مختلف.

التغييرات الإضافية للشاشة/FPS وFlashfix متوقفة في config المولدة؛ لا نجرب memory offsets خاصة بـ5187 على5517. تشغيل اللودر نفسه وhooksه لا يزال خطوة تحقق على جهازك، ولم يُنفذ داخل هذه المهمة. لو الأداة رفضت الإصدار، ابعت رقمFileVersion ورسالة الرفض؛ لا تفرض رقمversion.dat يدويًا.

لإنشاء ملف config للمراجعة **من غير نسخ أي شيء داخل العميل**:

```powershell
.\setup\Install-ClientConfig.ps1 -GenerateOnly
```

## 6. دخول أصدقاء عبر Hamachi — اختياري وبصلاحية واضحة

الأدوات لا تفتحfirewall تلقائيًا. بعد اختبارك المحلي، لو محتاج أصدقاء محددين يدخلوا، توجد `setup/Allow-Hamachi.ps1` وتحتاج PowerShell مرتفعة الصلاحيات واختيارIPsهم صراحة. تدعم `-WhatIf` للمراجعة أولًا، وتضيف قواعد للمنفذين9958/5816 ولعنوانHamachi وبرنامجي السيرفر فقط. لا تفتح3306/9865 ولا تعدّل الراوتر، ولا تعيد كتابة قواعد موجودة تلقائيًا.

## المهم قبل اعتبار اللعبة جاهزة

- نجاح الإعداد/التشغيل المعزول ليس اختبارعميل TQ على جهازك، ولا ضمانًا للقتال والحفظ والاقتصاد تحت الضغط.
- مدنVIP الخمس وساحاتها لها routes محددة؛ الوجهات التفصيلية غير المتحققة وteamteleport ترد برسالة، وليست ميزات مكتملة.
- ثبات طويل المدة، atomicity للتجارة، بقيةالحروب والأحداث وFan/Tower/Steeds/Arsenal والتوازن تحتاج اختبارات لعب لاحقة. لا تعتمد هذه النسخة كسيرفرعام أو اقتصادمدفوع بمجرد أنها تبدأ.
- قبل أي تحديث بعد وجود لاعبين، اعملbackup للداتابيز عبر أدواتك، واحتفظ بـ`.local` محليًا؛ لا تبنِ فوق تشغيل حي.

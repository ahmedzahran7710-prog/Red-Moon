# تصحيح خطأ المسار عند فتح ملفات التشغيل — 2026-10-29

## ما الذي حدث؟

المستخدم فك حزمة Windows في المكان الصحيح، ثم ظهر:

```text
Split-Path : Cannot bind argument to parameter 'Path' because it is an empty string.
Setup-RedMoon.ps1:3
[string]$Root = (Split-Path -Parent $PSScriptRoot)
```

الخطأ داخل القيمة الافتراضية للـparameter، **قبل جسم الإعداد**: لا اتصال DB أو استيراد SQL من هذه المحاولة. الاختبار السابق كان يمرر `-Root` و`-ProfilePath` صراحة؛ نجاحه لم يغطِّ طريقة الدبل كليك بلا معاملات. أُعيد إنتاج النمط القديم بشكل مستقل على Windows PowerShell 5.1، ولم يصل إلى جسم السكربت.

## تنزيل التصحيح للحزمة الموجودة

الملف الداخلي هو نفسه الذي قُدّم مباشرة في المحادثة: **31,723 بايت**، ويستبدل **11 ملف تشغيل فقط**. لا حاجة لإعادة تنزيل السيرفر كله.

1. اقفل نافذة الخطأ، ولا تحذف أي قاعدة أو ملفات قديمة.
2. فك محتويات **ملف التصحيح الداخلي** مباشرة فوق `F:\AhmedZahran\RedMoon\RedMoon-Sorce`.
3. وافق على استبدال ملفات CMD وملفات PS1 الستة فقط؛ **ادمج الملفات داخل `setup` الموجودة، ولا تحذف المجلد أو محتوياته الأخرى**. لا تشغّل السكربتات من داخل ZIP أو من مجلد تصحيح منفصل.

5. لو ظهر خطأ آخر، توقف عنده وأرسل نصه/صورته بعد إخفاء الأسرار؛ لا تعد الاستيراد يدويًا ولا تحذف قواعد.

## الإصلاح المحدود

- ستة scripts تستخدم defaults فارغة، وتستنتج المسار بعد parameter binding من ملف السكربت الفعلي، لا من مجلد النافذة الحالي.
- يحتفظ `-Root` و`-ProfilePath` الصريحان بقيمتهما، ولا يُفرض مسار خاص بالمالك داخل الكود.
- خمسة CMD تمرر المسارات صراحة، وتختار Windows PowerShell النظامية، وتراعي المسافات والرموز والشرطة الخلفية النهائية، وتنقل exit code بدل إخفاء الفشل.
- الحد الأدنى معلن: Windows PowerShell 5.1. لا تغيير لسياسة التنفيذ العامة أو antivirus؛ تظل السياسة الحالية للـprocess فقط كما كانت.
- تحفظ `.gitattributes` بايتات ملفات التشغيل عبر المنصات. يستخدم التصحيح الصغير ZIP_STORED حتى لا تختلف بايتاته بسبب إصدار مكتبة الضغط.
- **لا تعديل لكود اللعبة أو `Common.ps1` أو `owner-profile.json` أو SQL أو بيانات/`.local` أو executables.**

### ملاحظات التدقيق

أول run `40869066980` أعادت العيب القديم واجتازت مسارات السكربتات المصححة، لكنها توقفت عند فرضية في harness تساوي بين PowerShell provider location وRoot داخل مسار به `[]`. سجّلنا provider location كملاحظة بدل اعتبارها عقدًا، مع إبقاء فحوص Root/ProfilePath ونسخة الـhost وexit codes. نجحت الجولة `40869359602` كاملة، ثم نجحت `40869693318` بعد تثبيت بايتات التغليف.

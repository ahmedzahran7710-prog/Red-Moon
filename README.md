# Red Moon Classic+

سورس Conquer Online لعميل **5517**، مبني على المصدر المرخّص FoxConquer5517، مع تنظيم فعلي لمشاريع العمل باسم **RedMoon**.

**النسخة الجديدة ليست ملف تنظيم صغيرًا يُفك فوق القديم.** أسماء المجلدات والمشاريع والـnamespaces والـEXEs تغيّرت. لا تخلط ملفات النسختين، ولا تحذف تثبيتك القديم أو `.local` أو قواعدك.

## ابدأ من هنا

- **عندك سيرفر مثبت وحسابات؟** اقرأ [START-HERE.md](START-HERE.md) ثم [دليل الانتقال الآمن](docs/MIGRATION.md). الحزمة الكاملة تُفك في مجلد جديد، ثم `Migrate-RedMoon.cmd` بدل إعادة Setup.
- **عايز تعدّل الكود؟** افتح `Open-RedMoon-Source.cmd` أو [src/RedMoon.sln](src/RedMoon.sln). [خريطة السورس](docs/SOURCE-MAP.md) توضّح مكان كل جزء.
- **تثبيت جديد تمامًا بلا قواعد موجودة؟** [دليل Windows](docs/LOCAL-WINDOWS.md). Setup يرفض استبدال أي قاعدة أو مستخدم قائم.

## مشاريع السورس

```text
src/
├── RedMoon.sln
├── RedMoon.AccountServer/   ← تسجيل الدخول وربط خادم اللعبة
├── RedMoon.GameServer/      ← الشخصيات والعالم والعناصر وأنظمة اللعب
├── RedMoon.Data/            ← Entities / Mappings / Repositories
├── RedMoon.Core/            ← الشبكة والباكتات والتشفير والمساعدات
└── RedMoon.Admin/           ← أداة الإعداد، وليست سيرفرًا ثالثًا
```

داخل GameServer، أنظمة اللعب في `Gameplay`، ومهام التشغيل في `Runtime`، واتصال اللاعبين في `Network/ClientTransport` والربط بالأكونت في `Network/AccountLink`. أسماء ملفات الباكتات تتبع أنواعها، وأسماء ملفات المعالجة تنتهي بـ`Handler`.

**ملفات التشغيل الجديدة:** `RedMoon.AccountServer.exe` و`RedMoon.GameServer.exe` داخل `server`. التشغيل من `Start-RedMoon.cmd`؛ الإيقاف والحفظ من `Stop-RedMoon.cmd`. فتح الحل أو تعديل C# لا يبدّل ملفات التشغيل تلقائيًا؛ لا تستخدم F5 أو EXE مباشرة لتجاوز تجهيز الأسرار، ولا تبنِ فوق تثبيت حي.

## الحزمة الكاملة والتحقق

التسليم الجاهز هو **`RedMoon-Windows-x64.zip`** في [إصدارات المستودع الخاص](https://github.com/ahmedzahran7710-prog/Red-Moon/releases)، بعد نجاح التحقق ومراجعة الإصدار. لا تستخدم إصدارًا Draft أو نتيجة فاشلة كتسليم نهائي.

- تحتوي الكود المعدّل كله، تشغيل Windows x64 ذاتي الاحتواء، الداتا المرجعية، بذور تثبيت نظيفة وحقوق الاعتماديات. لا تحتاج SDK أو Python **للتشغيل**، ولا تتضمن عميلًا أو لودرًا أو حسابات قديمة أو أسرارًا.
- `Code → Download ZIP` والملفات التلقائية المسماة **Source code** ليست حزمة تشغيل.
- `bundle-manifest.json` يسجل commit المصدر وبصمة كل ملف؛ تقرير ZIP يسجل حجمها وبصمتها. تقارير Windows المرفقة توضّح نطاق التحقق الفعلي. راجع [سياسة التحقق](docs/VERIFICATION.md)، ولا تعتبر وجود كود الاختبار دليلًا على تنفيذه.
- الحزمة الصغيرة القديمة `RedMoon-Source-Layout.zip` وتصحيح الـlaunchers القديم **تاريخيان وغير مناسبين للهيكل الجديد**.

المالك دخل اللعبة فعلًا على النسخة السابقة. هذا دليل محلي سابق، وليس إثباتًا لنجاح النسخة الجديدة أو اكتمال كل أنظمة اللعب. قبول النسخة الجديدة على جهازه يتطلب تجربة الحساب والشخصية بعد الانتقال مع الاحتفاظ بالقديم والنسخ الاحتياطية.

## حدود التغيير وطريقة العمل

هذه إعادة تنظيم وتسمية وتحديث أدوات التشغيل، وليست تغييرًا للكلاسات أو rates أو الاقتصاد أو امتيازات GM/VIP أو الجداول أو صيغة الباكتات. تبقى أسماء البروتوكول والجداول والتبعيات وحقوق المؤلفين الأصلية كما يلزم للتوافق والترخيص.

- الاختبارات وCI **بالطلب فقط**؛ كلا الـworkflows يدوي. طلب التحقق لهذه الإعادة لا يعيد التشغيل التلقائي لكل تعديل لاحق.
- [ميموري.md](ميموري.md) تُقرأ قبل أي تعديل، و[AGENTS.md](AGENTS.md) يوضح قواعد العمل والحفاظ على الداتا.
- [الأصل الثابت](https://github.com/ahmedzahran7710-prog/Red-Moon/tree/main/vendor/FoxConquer5517) و[تقارير التدقيق التاريخية](https://github.com/ahmedzahran7710-prog/Red-Moon/tree/main/audit) محفوظة في GitHub، منفصلة عن سورس العمل. لا نضع نسخة ثانية من السورس القديم في حزمة التشغيل حتى لا تختلط عليك.

**الأسرار محلية:** `.local` وخزنة DPAPI والـlogs ونسخ قواعد اللاعبين لا تُرفع أو تُرسل في المحادثة. الانتقال الحالي على نفس الكمبيوتر وبنفس حساب Windows؛ لا يعالج نقل خزنة DPAPI إلى جهاز/مستخدم آخر. معلومات البروفايل تخص المستودع الخاص؛ لا تنشرها للعامة.
